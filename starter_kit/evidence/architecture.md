# LoomQ 系统架构说明

## 整体架构

LoomQ 采用分层架构，将用户交互、L2 Agent、量子程序验证以及真实量子设备执行进行解耦。

整体流程：

```
用户
 |
 v
Web 交互层
 |
 v
L2 Agent
 |
 +----------------+
 |                |
 v                v
目标规格/验证      程序转换
 |
 v
量子执行适配层
 |
 +----------------+
 |                |
 v                v
Origin Quantum   SpinQ Cloud
 |
 v
真实量子设备
```

## Web 交互层

负责用户完整体验流程：

- Learn：量子电路学习、QASM 查看、状态变化展示以及实验入口；
- Explorer：自然语言生成量子程序；
- Repair：错误 OpenQASM 诊断与修复；
- 执行平台选择：选择目标执行环境并查看结果。

## L2 Agent 层

负责自然语言到量子程序的转换：

1. 接收用户需求；
2. 生成 OpenQASM；
3. 生成目标规格；
4. 执行语法与语义验证；
5. 在不满足目标时生成修复候选并再次验证。

## 验证层

负责检查 Agent 输出结果，包括：

- OpenQASM 解析；
- 电路结构检查；
- 目标态验证；
- fidelity 检查；
- 修复结果验证。

## 量子执行适配层

提供统一执行入口：

- 本地模拟执行；
- Origin Quantum Cloud 真机执行；
- SpinQ Cloud 真机执行。

不同平台 SDK 使用隔离运行环境，避免第三方依赖冲突。

## 工程运行层

工程化能力包括：

- Docker 化运行环境；
- Web 与后端服务构建；
- evaluator 自动化验证；
- 真机执行环境配置。

通过统一构建流程保证在干净环境中的可复现运行。
