# LoomQ Optimization Backlog

> 这是一份阶段性优化候选清单，不属于当前主线任务。
>
> 当前原则：先完成赛题客观能力与正式提交要求，保持已稳定的 L1/L2 主路径不做无必要重构；主线完成后再集中评估这些候选项。

## 使用方式

- 只记录可验证、可落地、且与当前能力边界相关的优化点。
- 不因为出现新的想法就立即修改稳定代码。
- 待 L2/L3/提交链路完成后，统一做一次优先级评估，再拆成正式 task。
- 每项最终只做三种决策：`吸收` / `调整后吸收` / `不做`。

## 当前优化候选

### Agent 正确性

- [ ] **生成后做语义自验**：Parser/白名单校验只能证明 QASM 合法，不能证明实验目标正确。可考虑实际运行模拟器，将结果分布与用户目标进行比较，不通过时再触发修复。
- [ ] **目标判定与代码生成解耦**：避免同一次模型调用同时“理解目标 + 生成电路 + 声明目标”，否则模型可能把目标理解错后仍自洽通过。可评估使用独立 Judge（只看用户原话）生成验收目标，再对生成电路做语义验证。
- [ ] **对“标签冲突”和“电路真的错了”分开处理**：当目标族标签与实际分布冲突时，不要直接拿错误标签去反向修坏正确电路；可基于用户原始请求 + 模拟器真实分布做一次定向裁决，异常时仍按保守失败处理。
- [ ] **后端选择尽量确定性**：模型负责提取自然语言约束，最终后端筛选由 `backend_capabilities.json` 等确定性数据完成，减少模型记忆/幻觉导致的错误。
- [ ] **明确无法精确验证的边界**：对于无法推导理想分布的任意目标，不伪装成已经语义验证；至少做结构校验，并在产品层说明验证覆盖范围。

### Agent 会话与鲁棒性

- [ ] **评分入口与产品会话分离**：`agent_chat(prompt)` 保持无状态、符合自动评测；用户入口可以维护独立 session，支持“改成 5 比特”“换成真机”等连续修改。
- [ ] **为模型异常输出准备降级路径**：结构化响应缺字段、JSON 围栏、额外文字、错误任务分类等情况应能解析或安全失败，避免单轮异常导致整个体验崩溃。
- [ ] **生成失败时提供真实反馈再修复**：修复 prompt 优先携带 Parser/Simulator 得到的具体问题，而不是笼统要求“再试一次”。
- [ ] **修复重试保留历史最优候选**：模型重试可能越改越差；若多轮都未完全通过，可按明确的语义验证指标保留历史最佳版本，并明确标注未完全验证，避免机械返回最后一版。

### 验证与回归

- [ ] **评估增加轻量参考态矢模拟器**：用尽量少的依赖独立计算理想 statevector / distribution，可同时服务 L2 语义自验、门分解验证、离线回归，以及后续 Quantum DevTools 的逐门状态轨迹；不要让正确性验证完全依赖三方 SDK。
- [ ] **回归样例必须具备“暴露目标错误”的能力**：位序测试使用非对称状态，相位/受控相位测试选择对相位错误敏感的电路，避免 Bell/GHZ 这类回文分布或天然均匀分布让实现错误也通过。
- [ ] **关键验证尽量做差分或独立裁判**：同一实现既生成结果又生成期望值时存在共同错误风险；核心路径优先使用独立参考实现、手算固定样例或另一条执行链做交叉验证。

### 交互与引导

- [ ] **首页提供具体自然语言示例**：不要只放“请输入量子实验需求”。给 3–4 个可以直接点击/填入的真实请求，让零量子背景用户知道自己可以怎样表达。
- [ ] **围绕“用户下一步想做什么”组织操作**：避免把“生成 / 修复 / 后端选择”直接作为产品菜单。根据当前状态动态提供 Quick Actions，例如“单步看看”“直接运行”“为什么是这个结果”“让 Agent 修复”“换真机运行”。
- [ ] **引导跟随操作出现，而不是独立教程前置**：用户第一次生成/执行时按上下文展示一句解释或可选“为什么”，不要求先学完量子概念再使用。
- [ ] **结果必须可视化**：最终 counts/probability 至少用清晰的分布图展示，让用户能一眼看到主峰、零概率项和噪声，而不是只读 JSON/文本数字。
- [ ] **真机等待过程要有可观察进度**：提交真机后及时展示已选平台、任务编号、当前等待/执行状态；超时或真机不可用时允许安全回落模拟器，不让用户面对长时间无输出。
- [ ] **真机结果与理想结果并列解释**：结构性结论以无噪声模拟器的理想分布为基准，真机数据用于解释噪声、泄漏和峰值偏差，避免直接从带噪分布猜“电路本来想做什么”。

### 产品差异化：Quantum DevTools

- [ ] **保留 DevTools 作为核心交互隐喻，但弱化“只给 Web 开发者”标签**：目标用户可描述为“没有量子背景的软件开发者 / AI 编程用户”。
- [ ] **QASM ↔ Circuit 双向定位**：代码行与量子门同步高亮，让 Agent 生成的代码具备可审查性。
- [ ] **模拟器单步执行**：提供 reset / previous / next / run-to-end；明确说明中间状态来自理想模拟器，不是假装真实 QPU 可以随意打断点读取状态。
- [ ] **展示执行前后状态 Diff**：优先验证概率分布、非零基态、振幅/相位等哪些信息真正对开发者有帮助，再根据人工使用反馈精简。
- [ ] **Agent 修复后可比较 Diff / 执行轨迹**：不仅告诉用户“修好了”，还让用户看到哪一行、哪一步导致结果变化。

### 真机证据与提交收尾

- [ ] **原始平台返回与归一化结果分开留存**：真机原始 payload 不修改，另生成符合统一 Schema 的归一化结果；文档明确位序、shots 补偿等转换规则，并尽量提供可复算脚本。
- [ ] **真机平台计分口径提交前单独核对**：区分“同一云平台上的不同设备”与“不同平台/provider”，不要仅凭设备数量推断可获得多个平台的真机加分。

### L3 / Bonus 若进入

- [ ] **L3 用随机程序 + 穷举测量值做差分测试**：参考解释器计算经典块期望终态，再与生成的 RISC-V 在官方模拟器上的执行结果逐项比对；同时保留少量手算固定样例降低共同错误风险。
- [ ] **自定义量子 RISC-V 不只停在助记符**：若做 Bonus，优先把 opcode/字段编码、编解码实现和端到端语义测试三件事对齐，并用非对称电路验证 qubit 索引与字段映射。

## 暂不执行

以上条目目前全部视为主线完成后的候选优化，不应打断：

1. L2 客观能力完成与稳定性验证；
2. L3 / Bonus 的取舍与实现；
3. Docker / submission / evidence 等正式提交闭环。

后续发现新的有效优化点，只追加真正有价值且不重复的条目。
